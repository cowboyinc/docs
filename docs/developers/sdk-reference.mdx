### `emit_event`

```python
emit_event(name: str, payload: Any, *, schema: bytes | None = None) -> dict
```

Send an event to the chain and return its EmitResult dictionary.

Optional ``schema`` is a 32-byte payload schema identifier. Explicit
declarations must match every explicitly typed subscriber. The identifier
describes the codec and schema agreed by the parties; payload bytes are not
parsed or validated by the node.

``emit_id`` identifies this emit within the transaction (starting at 1).
``sync_outcomes`` contains attempted or skipped synchronous deliveries in
subscription order: ``sub_id`` (33-byte ID), ``status`` (0 success, 1 handler
error, 2 skipped/refused), and ``gas_used`` (inclusive subtree cycles).
``deferred_subs`` lists IDs queued for deferred delivery, including Access
overflow. Delivery remains subject to transaction commit and child admission.

Encoding: canonical CBOR (invariant I-1), plus a raw hatch keyed on the
payload's *type*.

- bytes-like (``bytes``/``bytearray``/``memoryview``): the raw hatch — sent
  verbatim, for a payload that is already serialized.
- anything else: canonical CBOR via ``codec.encode``. ``None`` emits CBOR
  null, the faithful encoding of the value that was passed.

Raises ``CodecError`` for a value the codec cannot encode, and for a str that
is already serialized JSON (see ``_reject_json_string``).

NOT interchangeable with ``send()``, which shares only the non-bytes -> CBOR
rule. ``send()``'s hatch is the ``raw=`` keyword, not the type, so
``send(t, b'x')`` CBOR-wraps the bytes where ``emit_event(t, b'x')`` passes
them verbatim; ``send(t)`` encodes ``b''`` where ``emit_event(t, None)``
emits CBOR null; and ``send()`` has no JSON-string guard.

NOTE (consensus): the encoded bytes are committed — the host folds them into
`compute_logs_root` -> `receipt_root`, and bills cells per encoded byte. See
the flag-day note in docs/dev/cip29-event-hooks.md before changing anything
here that moves the bytes.

### `renounce_ownership`

```python
renounce_ownership() -> None
```

Permanently abandon ownership of this actor.

Sets ``__OWNER__`` to the zero address. After this call any
``@callable_by(OWNER)`` handler becomes unreachable, and ownership cannot
be re-established (``assume_ownership_if_unowned`` treats a zero-address
owner as still set). The state change is irrevocable.

Auth rules mirror ``transfer_ownership``:

* If no owner is set, ANY caller may renounce.
* Once set, only the current owner (or an intra-actor call) may renounce.

Raises
------
PermissionDeniedError
    If a non-owner tries to renounce after ownership has been
    bootstrapped.

### `scan_state_prefix`

```python
scan_state_prefix(prefix: bytes, limit: int = 100) -> list[tuple[bytes, bytes]]
```

Return up to `limit` ``(key, value)`` pairs from on-chain storage whose
user-key starts with ``prefix``, in ascending key order (Model C).

Semantics:
- Only keys stored in verbatim mode (≤32 bytes) are visible; long keys
  (hashed mode) are never returned by prefix scan.
- ``limit`` is clamped to ``MAX_PREFIX_SCAN_LIMIT`` (1000) by the host.
- Pricing: ``500 + limit × 50`` cycles (by ``limit``, not returned
  count — prevents "wide scan narrow filter" free lunch) plus
  ``sum(len(k)+len(v))`` cells for returned entries.

Pagination: pass the last returned key (appended with ``b"\x00"``) as
the next ``prefix`` to continue past the current page — or use the
higher-level ``/actors/{addr}/storage`` RPC for offset/cursor pagination.

Returns ``[]`` when no key matches the prefix.

Example:
    entries = scan_state_prefix(b"user:", limit=50)
    for key, value in entries:
        ...

### `call_actor`

```python
call_actor(target: bytes, method: str, payload: bytes, cycles_limit: int, access_limit: Optional[int] = None) -> bytes
```

Synchronously call a method on ``target`` (0x-str / 20-byte bytes / Address).

Low-level binding (payload is sent verbatim); prefer ``call()`` for object args.
``access_limit`` is unscaled nested-frame access authority. The SDK encodes
omission as the raw-host ``0`` sentinel, which grants floor(63/64 of the
caller's remaining authority). The Python SDK rejects an explicit SDK ``0``;
the preserved raw ABI collapses literal ``0`` and omission to that default,
so the host's ``Some(0)`` rejection is defense in depth and is unreachable
through this runtime. Strictness is inherited: a child is strict if its
parent is strict or allowance is below remaining. At remaining ``1``, the
default is ``0 < 1`` and strict/catchable; at remaining ``0``, it is ``0 ==
0`` and non-strict/fatal.

### `schedule_timer`

```python
schedule_timer(height: int, payload: bytes) -> bytes
```

Schedule a timer that fires at `height`, delivering `payload` to the
calling actor. Requires the ``timer.schedule`` entitlement. Returns a
timer id (opaque bytes) that can be passed to ``cancel_timer``.

Uses protocol defaults for ``fee_payer`` (actor pays itself),
``gas_limit`` (``TimerConfig.max_cycles_per_fire``), ``access_limit``
(``DEFAULT_TIMER_ACCESS_PER_FIRE``), and ``expires_at``
(``current_height + TimerConfig.max_ttl_blocks``). Use
:func:`schedule_timer_ex` to override any of these.

### `schedule_timer_ex`

```python
schedule_timer_ex(height: int, payload: bytes, fee_payer: Optional[bytes] = None, gas_limit: Optional[int] = None, access_limit: Optional[int] = None, expires_at: Optional[int] = None) -> bytes
```

Model B schedule with actor-specified economics (CIP-5 §4.1).

Args:
    height: block height at which the timer fires; MUST be strictly > current.
    payload: opaque bytes delivered to the handler (max 1 MiB).
    fee_payer: address debited at each fire (0x-str / 20-byte bytes /
        Address). ``None`` → actor pays itself. Rejected values: ZERO
        address and the reserved system-actor band ``0x01..=0x0F``.
    gas_limit: per-fire cycle cap. ``None`` → ``TimerConfig.max_cycles_per_fire``.
        Must be ≤ the config cap; ``0`` is rejected.
    access_limit: declared per-fire committed-store access request.
        ``None`` → ``DEFAULT_TIMER_ACCESS_PER_FIRE``. Must be ≤ the
        protocol Timer access cap; ``0`` is rejected.
    expires_at: absolute block height after which the timer self-destructs.
        ``None`` → ``current_height + TimerConfig.max_ttl_blocks``. Must
        be strictly > current and ≤ ``current + max_ttl_blocks``.

Returns the timer id (opaque bytes).

Example — deployer-funded oracle timer with a tighter budget::

    timer_id = schedule_timer_ex(
        cowboy_sdk.current_block() + 10,
        b"",
        fee_payer=self.deployer,
        gas_limit=200_000,
        access_limit=32,
        expires_at=cowboy_sdk.current_block() + 2_592_000,
    )

### `subscribe_event`

```python
subscribe_event(emitter: bytes, topic: bytes, handler: str, gas_prepaid: int, bid: int = 0, *, schema: bytes | None = None) -> bytes
```

CIP-29 §2.1: subscribe to a (emitter, topic) for synchronous fan-out.

Charges the calling actor:
  - SUBSCRIPTION_REGISTRATION_FEE cycles (burned, not refundable)
  - bid cycles (burned, not refundable)
  - gas_prepaid cycles (held in gas_remaining, refundable via unsubscribe_event)

Raises:

    HostError: gas_prepaid below MIN_SUBSCRIPTION_GAS_PREPAID; >= 512 subscribers

### `call`

```python
call(target, method: str, args = None, cycles_limit: int = 100000, *, access_limit: int = None, codec: str = DEFAULT_CODEC)
```

Synchronously call a method on the target Actor.

Parameters
----------
target : bytes | str | Address
    Target Actor address (20-byte Ethereum address).
method : str
    The method name to call.
args : any, optional
    Arguments to pass to the method, encoded with ``codec``. Under an
    encoded codec, ``None`` sends *no payload* (empty bytes) rather than an
    encoded value, so it is distinct from ``[]`` — which encodes as ``0x80``
    under ``"cbor"`` and as ``[]`` under ``"json"``. A callee that decodes
    its payload sees the difference. Under ``"raw"``, ``args`` must be bytes
    and is sent verbatim (pass ``b""`` for no payload).
cycles_limit : int
    Maximum number of Cycles this call may consume, default 100,000.
access_limit : int, optional
    Positive structural Access allowance for the nested frame. When
    omitted, the host grants floor(63/64 of its remaining authority),
    reserving the balance for the caller to finish.
codec : str
    Codec for both the arguments and the return value — one of
    ``payload_codec.CODECS``, default ``"cbor"``. It must match the
    ``decode=`` the target handler declares: the codec is chosen by the
    caller and is not carried on the wire (the ``ExecuteActor`` payload is
    opaque bytes), so nothing on the callee side can correct a wrong pick.
    A mismatch usually raises — a ``CodecError`` from the callee's decode,
    or a decode failure here on the return — but small scalars can
    misdecode silently, so treat the callee's declared codec as part of its
    signature.

Returns
-------
any
    The return value of the target method, decoded with ``codec``.

Raises
------
ActorNotFoundError
    The host returned ``NotFound``. Typically no actor is deployed at
    ``target``, but an existing system actor also returns ``NotFound`` for a
    resource it cannot find (an unknown subscription id, say), and the two
    are indistinguishable from the host code alone — so this does not prove
    the address is empty. At/above ``_CALL_ERROR_SHAPE_ACTIVATION_HEIGHT``
    the concrete class is ``_ActorNotFoundCallError``, which ``except
    ActorCallError`` also catches; below it, it does not.
CallDepthExceeded
    An in-process (local/checkpoint-mode) call chain overflowed Python's
    recursion limit. The on-chain 32-frame limit is NOT reported here: the
    host returns ``Forbidden`` for it — indistinguishable from a permission
    denial — so an on-chain depth overflow surfaces as ``ActorCallError``.
ActorCallError
    The callee raised, or the host rejected the call with any ``Forbidden``
    cause (depth limit, permission, re-entrancy).

Below the activation height the classification is the pre-unification one:
failures are sorted by message substring and the legacy message text is
used. Both are consensus state — see the constant.

### `StreamConsumerDedup`

```python
class StreamConsumerDedup
```

Consumer-side dedup for CIP-7's at-least-once push contract (COW-1512).

Stream push delivery is **at-least-once**: a consumer may receive the same
``(stream_id, sequence)`` more than once — e.g. a publisher/runner retry, or
a reconnect whose backfill overlaps already-pushed messages. Consumers MUST
therefore dedup by ``(stream_id, sequence)`` and process each pair exactly
once. Sequences are monotonic and gap-free per stream, but redelivery and
out-of-order arrival (live push racing a backfill fetch) are both possible.

Memory is bounded by a sliding window per stream: a contiguous ``floor``
(every sequence ``<= floor`` has been delivered) plus a set of out-of-order
sequences seen above it, which compacts into the floor as the gaps fill — so
steady contiguous delivery keeps only the floor, not every sequence ever
seen.

## Payload codecs — the handler/caller selector

_Module: `cowboy_sdk.payload_codec`_

### `normalize_codec`

```python

```

Validate a caller-side ``codec=`` argument, failing loud on an unknown one.

### `ok`

```python
ok(value)
```

Force ``value`` through the declaring handler's codec on return.

A bare ``bytes``/``None`` return from a ``decode=`` handler passes through
verbatim (bytes are treated as an already-serialized payload; None as "no
output"). Wrap the value in ``ok`` when you instead want it encoded as a
codec value — e.g. a CBOR byte string::

    @public(decode="cbor")
    def blob(self, payload):
        return ok(b"\x00\x01")   # -> CBOR byte string, not raw passthrough

``ok`` is only meaningful inside a handler declaring an encoded codec
(``"cbor"`` / ``"json"``); a raw handler's return is never re-encoded, so an
``ok`` value there is a bug the permission wrapper raises ``TypeError`` for.

### `decode_payload`

```python
decode_payload(payload, fmt)
```

Decode a raw inbound handler payload using the named codec.

``fmt`` is one of ``"raw"``, ``"cbor"`` or ``"json"``:

  * ``"raw"``  — return ``payload`` unchanged (the pre-decode contract:
    handlers receive the exact bytes the host delivered; no type check).
  * ``"cbor"`` — canonical CBOR decode (invariant I-1).
  * ``"json"`` — the strict JSON decode ``json_codec`` owns: UTF-8 only, no
    non-finite numbers, no surrogate escapes.

Both encoded codecs require a bytes-like payload; a non-bytes payload or any
decode failure (malformed bytes, over-nesting) raises ``CodecError`` (host
slug E1213).

An empty payload (no argument bytes) decodes to ``None`` for both encoded
codecs — symmetric with the return side, where ``None`` means "no output"
(``codec.decode(b"")`` / ``json_codec.decode(b"")`` would otherwise raise).
``raw`` returns the empty bytes unchanged.

### `encode_args`

```python
encode_args(value, fmt)
```

Encode caller arguments into the payload bytes the handler receives.

Mirror of ``decode_payload``: for a handler declared ``decode=fmt``,
``decode_payload(encode_args(v, fmt), fmt)`` is ``v``.

  * ``"raw"``  — ``value`` must be ``bytes``/``bytearray`` and is sent
    verbatim; anything else (``None`` included) raises ``TypeError``. The
    accepted set is the one ``send(raw=True)`` has always taken, whose hatch
    this generalizes.
  * ``"cbor"`` / ``"json"`` — ``None`` sends *no payload* (empty bytes),
    which a callee can tell apart from an encoded value; everything else is
    encoded, canonically for ``cbor`` and under the strict profile for
    ``json``.

A ``cbor`` encode failure propagates as the stdlib error ``codec.encode``
raised. It is deliberately not re-classified the way ``_encode_value``
re-classifies a handler return: this runs in the caller's own frame, where
the exception is the caller's to catch, not a fault the host has to slug.
``json`` still raises ``CodecError`` — its strict profile classifies its own
refusals, and a ``CowboyError`` is no harder for a caller to catch.

### `decode_return`

```python
decode_return(result, fmt)
```

Decode a handler's return, using the codec the call was made with.

Mirror of ``_encode_return``. ``None`` — the host's "no output" — stays
``None`` under every codec; ``"cbor"`` and ``"json"`` run their decoder;
``"raw"`` hands back exactly what the host returned, the same untouched
contract ``decode_payload`` gives a raw handler inbound. Not
``bytes(result)``: that would turn a local harness's non-bytes reply into
that many zero bytes.

An encoded handler that returns bare ``bytes`` passes them through
unencoded, so decoding those raises here unless the handler wrapped them in
``ok()``. That asymmetry is what ``ok`` exists to resolve, and it is the same
one a caller sees today; it is not introduced by the codec selector.

## Strict JSON codec

_Module: `cowboy_sdk.json_codec`_

### `encode`

### `decode`

The invariant is on the *value*, not on the bytes: whatever this returns,
``encode`` can serialize again, so a handler may pass its payload straight
back out. Input spelling is deliberately unconstrained — ordinary RFC 8259
that no encoder here would emit (whitespace, unsorted keys, duplicate keys
with last-wins, literal non-ASCII) is accepted and normalized on the way
back out. Demanding canonical input instead would reject what every stock
JSON encoder produces, which is the interop this codec exists for.

Refused is what would break that invariant:

  * UTF-8 only. ``json.loads`` on raw bytes sniffs for a UTF-16/32 BOM and
    would reinterpret the payload under an encoding nothing here emits.
  * no non-finite floats, spelled either as one of the bare tokens or
    through number syntax that overflows.
  * no surrogates (``_reject_surrogates``).

Raises ``CodecError`` (E1213) for each of those and for malformed JSON,
matching ``encode`` and ``codec.decode``.
